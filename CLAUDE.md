# CLAUDE.md — Phare

Standing instructions for every session in this repo. Rules, not suggestions.

## 1. Project

- **Phare** is a planning system for Canadian households. Bilingual EN/FR, live at
  https://phare.money.
- Never call it a budgeting app, an expense tracker, or a financial dashboard.
- Say **"household"**, never "family", in product copy, AI prompts, and docs.

## 2. Repo layout

pnpm workspace (`pnpm-workspace.yaml`: `packages/*`, `apps/*`).

| Path | What it is | What belongs there |
|---|---|---|
| `src/` (root) | Next.js 16 web app (`next` 16.2.7), next-intl, Supabase, Stripe, Anthropic SDK | Routes, API handlers, web UI, server-only logic. Messages in `src/messages/{en,fr}.json`; legal copy in `src/content/legal/` |
| `packages/core` | `@phare/core`, **source-only** (`exports` points at `src/index.ts`, no build step, no `dist/`) | Pure money/date logic shared by web and mobile: `businessToday`, recurrence materialization, `monthlyEquivalent`, `formatCAD*`, timeline display logic. No `next/*`, Supabase, `process.env`, `node:` builtins, or DOM |
| `apps/mobile` | Expo SDK 57 app (`@phare/mobile`), expo-router, development build (not Expo Go) | Mobile screens, its own i18n catalogue (`apps/mobile/src/i18n/messages/`), its own vitest config |
| `supabase/migrations/` | Versioned schema migrations | |
| `scripts/` | One-off `.sql` data repairs + `ensure-pnpm.js` preinstall guard | |
| `docs/tickets/` | Filed out-of-scope bugs | |

- **Mobile app code never imports from the web `src/`** — not code, not
  `src/messages` (which contain prices). Enforced by
  `apps/mobile/src/__tests__/sourceCompliance.test.ts`. The only exception is a
  test proving two import paths resolve to one function (`timelineView.test.ts`).
- If you are about to copy a function out of `@phare/core`, or re-implement one
  in `src/` or `apps/mobile`, that is the bug. Move it into core instead.
- Do not add a build step or Metro config for `@phare/core`; nothing needs one.

## 3. Commands

**pnpm only.** `npm install` is refused by `scripts/ensure-pnpm.js` (preinstall).
Run from the repo root unless noted.

| Task | Command |
|---|---|
| Install | `pnpm install` |
| Web dev server | `pnpm dev` (= `next dev --webpack`) |
| Web build | `pnpm build` |
| Web + core tests | `pnpm vitest run` (the `test` script is watch mode; `apps/**` is excluded) |
| Core tests only | `pnpm vitest run packages/core` |
| Web typecheck | `pnpm typecheck` (= `tsc --noEmit`; root tsconfig excludes `apps`) |
| Lint (whole repo) | `pnpm lint` |
| Lint mobile only | `pnpm exec eslint apps/mobile` |
| Mobile tests | `pnpm --filter @phare/mobile test` |
| Mobile typecheck | `pnpm --filter @phare/mobile typecheck` |
| Mobile bundle compliance | `pnpm --filter @phare/mobile bundle:check` (fresh Android export, then scans the Hermes bundle) |
| Mobile dev server | `pnpm --filter @phare/mobile start` |
| EAS build | from `apps/mobile`: `eas build --profile <development\|preview\|production> --platform <android\|ios>` |

- The web and mobile suites are separate on purpose. The root count is the web
  app's and must not move when mobile changes.
- `eas` is a globally installed CLI, not a repo dependency. Profiles live in
  `apps/mobile/eas.json`.
- `next build` and `next dev` share `.next/`. Check whether a dev server is
  running before building.
- Typed routes are regenerated by `expo start`, not `expo export`. A new route
  fails `typecheck` until Metro has run once.

## 4. Non-negotiable engineering rules

- **Code owns all math.** The AI only narrates figures that code computed. The AI
  never chooses a number, category, or source.
- **One source of truth per figure.** Never recompute a figure in parallel.
  Shared logic lives in `@phare/core`.
- **Real months, never averages.**
- **`businessToday(householdTimezone)` is the only date boundary.** Never
  `CURRENT_DATE`, `new Date()` read without a zone, or server-local time.
- **Balances sum transactions dated <= today.** Future-dated rows are plan, not
  balance.
- **Never rewrite history.** Rule edits are effective-dated (`splitRule`, in
  `src/app/api/recurring/[id]/route.ts`). The plans of closed cycles are locked.
- **Silent failure is worse than visible failure.** No swallowed errors, no generic
  message hiding the server's real reason, no `$0` standing in for "no data".
- **Reject oversized input; never truncate it.**
- **Bilingual EN/FR on every user-facing string.**
  - Web: `src/messages/__tests__/i18nKeys.test.ts` proves every `t()` key
    resolves in both locales. It cannot see hardcoded literals or dynamic keys,
    so check those by hand.
  - Mobile: `apps/mobile/src/__tests__/i18nParity.test.ts`.
  - Write the French as a native speaker would, not as a translation. Verify it at
    byte level: fr-CA currency uses U+00A0 as both the thousands separator and
    before `$` (pinned in `packages/core/src/__tests__/money.test.ts`).
  - Duplicate top-level JSON keys silently shadow earlier ones.
- **Mobile shows no prices, upgrade CTAs, pricing links, or steering copy**
  (App Store 3.1.1). Enforced over source by `sourceCompliance.test.ts` and over
  the compiled bundle by `bundle:check`. Core's source counts as mobile source.
- **Expenses never get member attribution.** Manual-entry routes default expense
  `member_id` to null, never to the creator.

## 5. Data changes

**Database reads**
- Every database read goes through the `supabase` MCP server, which runs
  `--read-only` (local scope, project `rmxnryjslussumwttzna`).
- **Never use `SUPABASE_SERVICE_ROLE_KEY` for queries**: not in scripts, curl
  calls, or ad-hoc clients. If the MCP server is not connected, stop and say so.
  Do not fall back to the key.
- **Never write `SUPABASE_ACCESS_TOKEN` into any file**: not `.mcp.json`,
  `.claude.json`, `.env*`, settings, scripts, or docs. The MCP server reads it
  from the environment.

**Migrations**
- Versioned in `supabase/migrations/`. Lineu applies them in the Supabase SQL
  Editor. Every migration ends with a VERIFY block.
- **A written migration is not a live migration.** Never report one as applied
  unless Lineu has confirmed it.
- `CREATE OR REPLACE FUNCTION` with a changed parameter list creates an
  **overload**. With an unchanged signature it can **silently drop clauses** from
  the body. Any change to `handle_new_user` (or any trigger function) needs a
  `SELECT prosrc FROM pg_proc WHERE proname = '...'` check that the full body
  survived.

**One-off data repairs**
- Write them as `.sql` only, in `scripts/`, in this order:
  1. a BEFORE select
  2. `BEGIN;`
  3. the statements, each with its expected row count in a comment
  4. `COMMIT;` on its own line
  5. a VERIFY select
- Scope every statement by `household_id`.
- Use literal dates, compared in the household timezone. Never `CURRENT_DATE`,
  which is UTC.
- **NEVER write `.mjs`, `.js`, or Node scripts that mutate data.**
- **NEVER leave harness or scratch scripts in the repo.** Put scratch work in the
  session scratchpad. Ask before writing anything that would be a standalone
  script.
- **Never run anything against the production database unprompted.**

**Live test household**
- The designated test household is **Zezinho Test** (`987c63c1…`). Its
  credentials are in `apps/mobile/.env.test.local` (gitignored — confirm
  before any change to it; never print the password, never copy it into any
  other file). Sign in with the publishable key, never the service-role key.
- **Live write tests are allowed only on Zezinho Test.** Every other
  household is read-only, always — household `2be22642` included.
- **Never delete Zezinho Test or cancel its Stripe subscription.** Deletion
  tests use throwaway accounts (T1, T2) created for the test.
- **Isolation tests** (cross-household writes, RLS, triggers) may write *from*
  Zezinho Test only when the target is a throwaway household created for the
  test — never a real household's rows. If the guard under test were wrong,
  the test itself would corrupt someone else's data.
- **Exclude Zezinho Test from every funnel and usage count.** Its events
  include test traffic (e.g. a `created_first_expense` logged by a test
  write on 2026-09-28).

## 6. Workflow

- **Risky changes** (money math, dates/materialization, auth, AI output, schema):
  diagnose first, report, then **STOP for approval** before changing anything.
- Deliver complete files and exact paths. Make one change at a time.
- **Mutation-test every new assertion.** It must fail against the pre-fix code.
  Report how many mutations were caught and how many survived.
- **Tests that pass while asserting nothing** are this repo's recurring failure.
  Watch for:
  - regex-on-source tests standing in for behaviour tests
  - assertions that pass because both sides are null or undefined
  - `echo` or pipes that hide a non-zero exit code. Check exit codes.

  Where a render harness exists, assert the rendered output. On web that means
  `src/components/savings/__tests__/renderProbe.test.tsx`. Mobile has no RN
  renderer; screen rendering there is unverified.
- **Passing tests are not verification.** Run the real query against the real
  database, and check query strings against the actual schema. State plainly what
  could not be verified on screen.
- **A declared type describes what can be there, not what is there.** When an
  external payload (Stripe, etc.) matters, log the real one.
- **Before reporting that nothing references X**, confirm the zero-match with a
  second tool. Grep has missed hits under `src/app/[locale]/`.
- **Read any pre-existing lint errors once**, even when you are not fixing them.
  Unused state, unused test destructures, and unused `t` instances are
  high-signal.
- **Out-of-scope bugs:** flag them and file them under `docs/tickets/`. Do not fix
  them inside the current change.
- Commit untracked work early. Only commit when Lineu asks.
- **Hiding a page does not hide its strings.** next-intl serializes the entire
  message tree into every page's HTML.

## 8. Known traps

- **Hermes string encoding.** Hermes stores a string with any non-ASCII
  character as UTF-16LE. A byte scan that does not decode both encodings cannot
  see French, including any U+00A0 currency figure. `\$\s?\d` over compiled output
  gives false positives. Use `apps/mobile/src/__tests__/complianceScan.ts`.
- **Stripe.**
  - `current_period_end` is on the SubscriptionItem, not on the Subscription (see
    `src/lib/stripeSubscriptionMap.ts`).
  - Portal cancellation sets `cancel_at`, not `cancel_at_period_end`.
  - The webhook re-retrieves live subscription state rather than trusting the
    event body.
- **`events.event_type` is unconstrained text**, and the quota/spend counters
  count rows in it. Clients may only write types in `CLIENT_EVENT_ALLOWLIST`
  (`src/lib/clientEvents.ts`). Never add a quota event type to that list.
- **Detached recurring rows** (`recurring_item_id IS NULL`) are invisible to
  joins on the rule. Find them via tombstones. Drift calculations must also
  exclude rows dated before `effective_from`.
- **`CREATE OR REPLACE` on a function can silently drop clauses.** See §5.
- **Timezone support on Hermes.** `assertTimeZoneSupport()` gates the whole mobile
  app because a runtime without full ICU silently ignores `timeZone`. Never replace
  it with manual UTC-offset math. It is deliberately not wired into the web app.
- **pnpm and Expo native peers.** pnpm floats `*` optional peers to their latest
  version. Pin them in `pnpm-workspace.yaml` `overrides`. pnpm 10 ignores
  `pnpm.overrides` in `package.json`.
- **Removing a member.** The member row cannot be deleted. A deleted member's
  tombstone must never count as a re-invite match.

## 9. Backlog

`docs/BACKLOG.md` is the single ordered list of what to work on next.

- At the start of every session, read `docs/BACKLOG.md`.
- When Lineu says "next", take the highest item marked READY that is not
  marked LINEU, and do it.
- Items touching money math, dates, auth, AI output, schema or deletion:
  diagnose first and STOP for approval, as §6 already requires. Everything
  else: build it and hand off.
- At the end of every task: update `BACKLOG.md` (move the item to Done with
  its commit hash, add anything new you found, re-order if needed) and commit
  it with the work.
- Never start an item marked FROZEN.
